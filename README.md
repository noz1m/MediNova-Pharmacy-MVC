# MediNova · Pharmacy & Wellness — MVC / .NET 10

Новый проект онлайн-каталога товаров для здоровья и приёма **заявок**, построенный вместо BookNest. Это **демонстрационное приложение**, не готовое решение для лицензируемой продажи лекарств. Реальная онлайн-аптека требует юридической проверки, регуляторной интеграции, подтверждения рецептов, безопасной оплаты, защиты персональных данных и процедур фармконтроля.

## Архитектура

- `Domain/Entities` — Category, Manufacturer, Product, Order, OrderItem
- `Domain/DTOs` — входные данные заказа и корзины
- `Infrastructure/Data/AppDbContext.cs` — EF Core mapping и PostgreSQL
- `Infrastructure/Services` — каталог и атомарное резервирование остатков при оформлении заявки
- `Infrastructure/DI/DependencyInjection.cs` — зависимости
- `MvcApp/Controllers`, `Views`, `wwwroot/css/site.css` — MVC интерфейс, адаптивный дизайн

## Запуск на Mac

Установи .NET 10 SDK и PostgreSQL. Сначала создай **отдельную** базу `medinova` (не используй базу BookNest!):

```bash
createdb -h localhost -p 5432 -U postgres medinova
```

В корне проекта задай секреты **один раз**, после этого повторять их не нужно:

```bash
dotnet user-secrets set 'ConnectionStrings:DefaultConnection' 'Host=localhost;Port=5432;Database=medinova;Username=postgres;Password=YOUR_PASSWORD' --project MvcApp
dotnet user-secrets set 'Admin:Password' 'CHOOSE_A_STRONG_UNIQUE_ADMIN_PASSWORD' --project MvcApp

dotnet restore
dotnet build MvcApp/MvcApp.csproj
dotnet run --project MvcApp --launch-profile http
```

Открой `http://localhost:5084`, админ-панель — `/Admin/Login`. Используй пароль длиной от 14 символов.

Локально можно хранить строку подключения в `MvcApp/appsettings.Development.json`, но **не загружай пароль в Git**: этот файл необходимо исключить из Git, если добавишь туда секреты. По умолчанию этот файл отслеживаемый и содержит только несекретную конфигурацию. User Secrets имеют приоритет над ним.

### Инициализация БД

Для **новой отдельной базы** в Development настроено `EnsureCreatedAsync`. Это создаёт таблицы без миграций и не удаляет данные. Для production **не используй** `EnsureCreated` вместо миграций. Создай полноценную начальную EF миграцию на *чистой* базе с отдельным миграционным workflow; нельзя смешивать существующие таблицы, созданные через `EnsureCreated`, с миграциями без корректного baseline. `Database:InitializeOnStartup` в production выключен.

### Порядок работы

1. В `/Admin/Login` войди с паролем, сохранённым в User Secrets.
2. Добавь категории и производителей.
3. Добавь товары и остатки. При первом старте в новой пустой базе будут автоматически добавлены **демонстрационные** товары (это не настоящий аптечный ассортимент). Отметь рецепт у рецептурных товаров.
4. Посетители могут искать товары, просматривать карточки, складывать нерецептурные товары в корзину и отправлять **заявку** с контактными данными.
5. В админке просматривай заявки, меняй статусы, скрывай товары. При отмене заявки остатки восстанавливаются.

**Безопасность:** административный раздел защищён cookie авторизацией и ограничением частоты попыток входа; все изменяющие POST-формы используют antiforgery-токены. Не используй систему для реальных продаж без полноценного security-аудита. Публичная форма принимает персональные данные — необходима политика конфиденциальности и регламент хранения/удаления.

## Проверки

Проверена файловая структура, JSON и целостность ZIP. .NET SDK в среде подготовки отсутствует, поэтому компиляция, живой браузер и PostgreSQL-сценарии **не проверены**. Проект требует локальной проверки `dotnet build`, прохода по страницам и тестирования операций перед использованием.


## Где находятся кнопки CRUD

1. Откройте `http://localhost:5084/Admin/Login` и войдите с паролем, заданным через `Admin:Password`.
2. После входа откройте **⚙ Админ-панель / CRUD** в верхнем меню (маршрут `/Admin`).
3. Раздел **Товары** (`/Admin/Products`) — кнопка «+ Создать товар», «Редактировать», «Скрыть» и «Восстановить». Товары из истории заявок не удаляются физически.
4. Раздел **Категории** (`/Admin/Categories`) — создание, изменение названия, удаление (если нет связанных товаров).
5. Раздел **Производители** (`/Admin/Manufacturers`) — создание, изменение и удаление (если нет связанных товаров).
6. Раздел **Заказы** (`/Admin/Orders`) — просмотр и обновление статуса. Отмена возвращает зарезервированные остатки.

**Почему CRUD не видно на витрине:** доступ к изменениям в каталоге должен быть только у сотрудников. Не используйте публичные CRUD-кнопки без аутентификации. Если пароль администратора не задан, вход не сработает; достаточно один раз задать его через `dotnet user-secrets set "Admin:Password" "<надёжный пароль не короче 14 символов>" --project MvcApp`.
